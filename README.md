# 排列五 V6.0｜雙模式完整歷史杀号排除系統

## 套件內容
- `index.html`：可直接部署到 GitHub Pages 根目錄的完整單頁網站，內嵌完整歷史資料。
- `draws-all.json`：完整歷史數據備份。
- `data/draws.json`：網站資料目錄格式的完整歷史備份。

## 完整歷史
- 共 7,780 期。
- 最早：04001（2004-11-14），號碼 92882。
- 最新：26305（2026-11-15），號碼 26081。
- 五位號碼以字串保存，保留前導零。只分析萬、千、百、十位。

## 雙模式
1. **智能自動模式**：只有每位置的逐期樣本外回測至少 100 次，且杀号成功率 95% Wilson 下界高於隨機成功基準 `1 - N/10`，才自動採用候選排除。未通過則只展示研究候選、不自動標記。
2. **固定數量排除模式**：每個位置按模型估計機率最低的 N 碼產生候選；N 可設 1–9。這是固定數量研究方案，不代表排除號碼不可能開出。

## 模型組成
多窗口平滑頻率、時間衰減、近期變化收縮、間隔弱特徵、相鄰期轉移、1–3 階條件轉移（樣本不足時回退收縮）、統計與特徵模型集成、逐期回測。四個位置獨立分析。

## 回測規則
- 預測某期時，只能使用該期之前的資料，禁止未來資料洩漏。
- 回測測試最近最多 1,200 期；每一期的訓練資料仍包含該期之前的全部歷史。此設計是為了讓手機瀏覽器可執行，不會刪除或縮減完整歷史資料。
- 排除成功：實際開獎數字不在排除集合內。隨機成功基準為 `1 - N/10`。
- 95% Wilson 下界只是一項統計門檻；多位置、多次模型嘗試仍可能造成選擇偏差，不代表未來優勢。

## 導入與保存
- 支援 JSON / CSV 手動導入，按期號合併；相同期號以新導入版本為準，並建立舊樣本快照。
- 本機使用 IndexedDB 保存，建議定期匯出備份。瀏覽器儲存並非真正無限容量。
- 不會自動連接官方 API。

## GitHub Pages 部署
1. 備份 repository 根目錄原有 `index.html`。
2. 將本套件 `index.html` 上傳至 `gdhkj/pailie5.GitHub.io` repository 的 `main` 分支根目錄並覆蓋。
3. Commit changes，等待 GitHub Pages 更新。
4. 開啟 https://gdhkj.github.io/pailie5.GitHub.io/；若仍見舊版，重新整理或關閉舊分頁再開。

## 重要聲明
若彩票開獎公平且獨立隨機，歷史資料不能讓任何數字成為「不可能開出」。系統只提供統計候選與歷史回測，不保證中獎、排除成功或未來持續優於隨機。
