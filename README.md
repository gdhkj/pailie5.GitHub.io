# 排列五 V5.2 多模型交叉杀号版

## 部署
把本資料夾內的 `index.html`、`manifest.webmanifest`、`sw.js` 上傳到 GitHub Pages 網站根目錄，覆蓋舊檔。

## 本版改動
- 不再用單一「出現次數多／少」直接杀号。
- 雙引擎分開計算：統計引擎（多窗口平滑頻率、時間衰減、近期偏差收縮）與歷史特徵引擎（間隔條件、相鄰期轉移、短期樣本），再以固定權重交叉集成。
- 新增1至3階連續條件轉移模型：例如查詢萬位最近為「6、6」時，回看歷史上萬位曾出現「6、6」後，下一期萬位分別開出哪些數字；亦同時分析單一前置數字及三位連續上下文。高階樣本不足時向低階分布收縮。
- 逐期樣本外回測：每一期只用之前的資料；只有至少100次測試且95% Wilson下界高於理論隨機基準，才自動建議杀号。否則顯示「暫不建議杀号」。
- 首次內建500期歷史樣本；所有新數據手動導入，沒有官方API或自動同步。可遷移部分舊版本機歷史資料。
- 新導入資料與本機歷史依期號合併；同一期號若號碼不同，以新導入版本作目前紀錄，舊版本先保存快照。最多保留12個導入前快照。
- 匯出備份包含目前資料及歷史快照。
- 不再下載 Qwen 或大型語言模型。瀏覽器本機數值引擎不需下載模型；它是統計特徵算法，不冒稱大型語言模型或神經網絡。

## 使用
1. 打開網站，內建500期樣本會載入本機。
2. 選擇 JSON 或 CSV 手動導入新開獎記錄；系統自動合併，不覆蓋舊期。
3. 執行智能自適應分析，查看四位置候選、驗證狀態及最近1至3位數字上下文的歷史後續分布。
4. 使用逐期樣本外回測檢查結果。
5. 定期按「匯出 JSON 備份」保存目前數據與歷史快照。

## CSV 格式
`期號,日期,號碼`，例如 `26306,2026-11-16,01234`。號碼必須保留完整五位及前導零。

## 重要限制
公平隨機開獎沒有可穩定利用的歷史規律；多模型只是比較不同歷史特徵，不能保證預測正確或提高中獎率。請以樣本外結果為準，不要只看候選號碼。

### V5.2 條件規律參與杀号（修正版）
- 連續條件轉移模型不再只是展示歷史統計，而是直接參與最終四位置杀号排序。
- 最終集成中，條件轉移模型約佔 27.5% 權重（特徵引擎 50%，其中條件轉移 55%）；其餘由統計、間隔、相鄰轉移及近期頻率等模型共同決定。
- 每個位置獨立分析最近 1 位、2 位及 3 位上下文的後續數字分布，並對高階小樣本作低階收縮。
- 分開顯示「連續規律模型候選」與「最終集成候選」，避免把單一規律誤當成確定結論。
- 自動選取仍須通過逐期樣本外驗證；未達標時顯示「暫不建議杀号」。
