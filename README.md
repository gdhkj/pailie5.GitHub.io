# 排列五 V4｜四位置智能自適應分析（手動導入版）

## 本版設定
- A：智能自適應；萬、千、百、十位分開分析。
- 每個位置預設候選排除 3 個數字；只有通過保留樣本驗證才自動啟用，否則顯示「暫不建議杀号」。
- 僅手動導入 JSON 或 CSV，不連接官方 API，不包含自動抓取腳本或 GitHub Actions。
- 導入資料保存在目前瀏覽器的 localStorage；請定期匯出 JSON 備份。清除瀏覽器網站資料可能令本機記錄消失。

## CSV 格式

```csv
期號,日期,號碼
20261115,2026-11-15,01234
20261114,2026-11-14,98765
```

號碼必須是完整五位數字，前導 0 必須保留。JSON 可使用陣列，或 `{ "draws": [...] }` 結構；每筆資料包含 `period`、`date`、`number`，亦支援常見欄位別名。

## V4 模型設計
候選模型包括 30/100/300 期平滑頻率、全歷史平滑頻率，以及半衰期 20/60/120 期的時間衰減模型。每個位置獨立評估。

每次分析將所選歷史窗口按時間切分：前 65% 作內部調參段，使用逐期向前驗證的平均 log loss 選模型；後 35% 作保留驗證段。保留段不參與選模。只有保留段至少 60 次測試，且排除命中率的單側 90% Wilson 下界高於相同排除數量的理論隨機基準 K/10，才自動啟用杀号。否則不自動排除。

這是一個保守的歷史驗證門檻，不代表統計上已證明未來優勢；重複嘗試不同窗口仍可能造成選擇偏差。回測結果不保證未來開獎。

## 逐期回測
逐期回測對每個目標期只讀取此前歷史資料，並在當時歷史內重新選模；同時以相同 K 個排除數字的隨機策略作比較。請確保導入資料期號完整、無重複、按期號可正確排序。

## GitHub Pages 部署
1. 將本資料夾內 `index.html`、`README.md`、`data/draws.json` 上傳至 repository 根目錄及對應子目錄。
2. GitHub Pages 選擇 `main` 分支、`/(root)`。
3. 打開網站，手動選擇 CSV/JSON 文件導入，或貼上 CSV 內容。
4. 導入後資料只保存在目前瀏覽器。若要在另一台裝置使用，請匯出 JSON 再於另一台裝置導入。

## 限制
- 只分析開獎號碼前四位（萬、千、百、十），不分析個位。
- 歷史頻率不能改變公平開獎下下一期各數字的理論概率。
- 本工具僅供統計研究，不含投注、收款、派彩功能。
